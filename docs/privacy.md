# プライバシー

翻訳はこの端末の中の PLaMo 3 Translate で行うので、**訳すテキストが手元から出ていくことはない**。
それでも ⌘C 2 回で動く道具は「いつクリップボードを読むか」がユーザーの操作から離れやすいので、
条件をここに書いておく。

| | |
|---|---|
| 翻訳で何を送るか | **何も送らない**。入力欄のテキストはアプリの中の llama.cpp に渡すだけ |
| いつ訳すか | 「翻訳」ボタン・`⌘/Ctrl+Enter`・キーボード監視で検出した ⌘C 2 回のいずれか |
| いつクリップボードを読むか | ⌘C 2 回を検出した瞬間に 1 回だけ。それ以外のときは本文を読まない |
| 常時見ているもの | OS の**クリップボード変更カウンタ**（書き込み回数の数値）だけ。中身は含まれない |
| 何を保存するか | 原文も訳文もディスクに書かない。書くのは設定（`settings.json`）とダウンロードしたモデルだけ |
| どこへも送らないもの | 設定（`settings.json`）は手元だけ。テレメトリ・クラッシュレポートの類は入れていない |
| Hugging Face に取りに行くもの | **モデルをダウンロードするときだけ**、ファイル一覧とモデル本体を GET する。送るのはリポジトリ名とファイル名（と再開時の範囲指定）で、原文・訳文・設定は含まない。ボタンを押したときにしか起きない |
| GitHub に訊きに行くもの | 起動時に「使ってはいけない版か」を、1 日 1 回「最新のタグは何か」を訊く。**送るのは GET だけ**で、原文・訳文・設定・識別子のいずれも含まない（[更新の通知とキルスイッチ](updates.md)） |

## 既定ではクリップボードを読まない

`double_copy_enabled` の**既定値は `false`**。新規インストール直後のアプリは
クリップボード変更カウンタも見ないし、当然その本文も読まない。トレイから開いて
自分で貼り付ける普通の翻訳アプリとして動く。

有効にするのは設定画面のチェックボックスからで、**初回だけ確認が出る**。
「コピーした内容をこのアプリが読み取る（翻訳は端末の中で行い、外部へは送らない）」「誤検出が起きれば
パスワードやトークンもウィンドウに表示されうる」ことを明示して、同意しない限りチェックは入らない。

同意したことは設定ディレクトリの `clipboard-consent` という空ファイルで覚えている
（`accessibility-asked` と同じ仕組み）。消せばまた確認が出る。

同意は「有効にしてよい」であって「有効である」ではない。あとからチェックを外せば、
読み取りはその場で止まる。手で `settings.json` を書き換えて有効にしようとしても、
読み込み時と保存時の両方で同意の有無を見ているので通らない。

## 誤検出したときに勝手に訳さない

クリップボード監視は「誰が書いたか」が分からない（[詳しくはこちら](how-it-works.md#音声入力ソフトによる誤爆クリップボード監視の限界)）。
音声入力ソフトの書き込みをコピー 2 回と取り違えることがあり、そのときクリップボードに
何が入っているかはアプリには分からない。

なので**クリップボード監視で開いたときは、入力欄に入れるところで止める**。翻訳は
`⌘/Ctrl+Enter` か「翻訳」ボタンを押したときだけ。取り違えても、自分のクリップボードが
画面に出るだけで終わる。翻訳は端末の中で済むので、どちらにしても外へは出ないが、
頼んでいないものが訳文欄に流れてくるのは邪魔なので止めておく。

**キーボード監視のときは即翻訳する。**こちらは ⌘C のキーコードそのものを見ていて、
音声入力ソフトが送る ⌘V とは混ざらない。つまり「2 回押した」は確かなので、
確認を挟む理由がない。

クリップボード監視でも即翻訳させたい場合は、設定画面の
「クリップボード監視のときも、開いた時点で自動的に翻訳する」で戻せる（既定オフ）。

| 検出方式 | ウィンドウを出す | 本文を読む | 翻訳する（端末内） |
|---|---|---|---|
| キーボード監視 | ✅ | ✅ | ✅ すぐ |
| クリップボード監視 | ✅ | ✅ | ⏸ 入力欄に入れて待つ（設定で即時にできる） |
| 無効（既定） | — | ❌ | ❌ |
