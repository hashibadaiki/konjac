# 更新の通知とキルスイッチ

**自動更新は入れていない。** 自動更新チャネルとは、リモートから任意のコードを全インストールに
入れられる常設の口のことで、署名鍵が漏れればそれが全部乗っ取られる。アクセシビリティ許可を
持つアプリでそれをやると、「脆弱性への備え」として入れたものが**より深刻な脆弱性の面**に
なる。しかも自動更新でも「強制」はできない — ユーザーが断ればそのままだし、アプリを
起動しなければ何も届かない。

代わりに、通知と停止の 2 つが入っている。速いのは後者で、**ダウンロードもインストールも
待たずに脆弱なコードの実行を止められる**。

| | いつ訊くか | オフにできるか | 何が起きるか |
|---|---|---|---|
| 更新の通知 | 1 日 1 回（`api.github.com` の最新リリース） | できる（設定画面の「新しいバージョンが出たら知らせる」） | メイン画面にバナー。押すと Releases がブラウザで開く |
| 告知（キルスイッチ） | 起動のたび（`security.json`） | できない | 翻訳を止めて、入れ替えを促す画面に切り替わる |

どちらも GET を投げるだけで、原文・訳文・設定・識別子の類は送らない。取得に失敗したら
（オフライン、GitHub 障害、レート制限）**素通りしてそのまま動く** — 状態確認が失敗した
だけでアプリが止まる方が、直そうとしている問題より重い。

バージョンの比較は `src-tauri/src/update.rs` にある。フロント側（`src/update.ts`）は取得を
するだけで、「止めるかどうか」の判断は Rust 側に置いてテストしてある。読めないバージョン
文字列は「比較不能」として**停止しない**方に倒す。

## 使ってはいけない版が出たときの手順

1. **止める。** `main` の `security.json` の `minimum_version` を、修正版の番号に上げて push。
   リリースは要らない。全インストールが次の起動で停止する（CDN のキャッシュがあるので数分）。

   ```json
   {
     "minimum_version": "0.3.1",
     "message": "0.3.0 以前はクリップボードの内容が意図せず送信されることがあります。0.3.1 に上げてください。",
     "url": "https://github.com/hashibadaiki/konjac/security/advisories/GHSA-xxxx-xxxx-xxxx"
   }
   ```

   `message` と `url` は任意。`url` は `https://github.com/hashibadaiki/konjac/` 配下しか
   開かない（Rust 側で弾く。Windows は `cmd /C start` を経由するので、シェルの記号を含む
   URL も同時に弾いている）。

2. **知らせる。** GitHub Security Advisory を公開し、脆弱なリリースの成果物を消して新規の
   ダウンロードを止める。

3. **直す。** 修正版をリリースする（[リリースの出し方](release.md)）。止まっている
   アプリの「新しい版を入手」からそこへ行き着く。

4. **解除は不要。** `minimum_version` を上げたまま置いておけば、修正版以降は普通に動く。
   誤って上げすぎた場合だけ、下げて push すれば次の起動で戻る。

`main` に push できる権限が、そのまま全インストールを止められる権限になる。ブランチ保護は
必須。ただしこれは「任意のコードを配れる」自動更新の署名鍵と比べれば、はるかに小さい範囲で済む。
